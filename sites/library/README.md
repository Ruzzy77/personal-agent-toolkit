# Library

Library의 문서 정본은 Sites D1에, 표지와 삽화는 Sites R2에 있습니다. 소유자는 각 발간호 주소에서 제목, 도입문과 본문을 바로 고칠 수 있으며 직접 입력한 내용은 잠시 뒤 자동으로 저장됩니다. ChatGPT, Codex와 Claude에서는 Personal Agent Toolkit의 `Library` 연결로 같은 문서를 읽고 고칩니다.

새 호는 `Library`의 이미지 업로드와 발간호 추가 기능으로 등록합니다. 이 폴더에는 사이트 화면, 문서 API와 편집기만 두고 원격 MCP는 `services/library`에서 관리합니다. 발간호 HTML, 카탈로그, 표지·삽화 원본과 제작 기록은 저장소에 보관하지 않습니다.

새 발간호의 원본 구조는 디자인 라이브러리의 **색인 · Library 발간호 HTML 틀**을
따릅니다. 발간 정보는 `.masthead`, 제목과 도입문은 `header`, 본문은 `article`에
두며 도입문 클래스는 `.lead`로 통일합니다. 새 호를 저장할 때 서버가 이 구조와 공용
본문 클래스로 정규화하므로 호마다 `<style>`과 읽기 도구를 다시 만들지 않습니다.
제목 영역은 제목 다음에 도입문이 이어지는 한 열로 구성하며 둘을 나란히 배치하지
않습니다. 본문의 문단, 절, 목록, 표, 수식과 이미지 순서는 글의 내용에 맞게 구성합니다.

발간 정보는 두 행으로 표시합니다. 첫 행에는 발간 유형, Digest 호수와 발간호 ID에
있는 예약 시각을 차례로 두고, 둘째 행에는 `DD MON YYYY` 형식의 날짜만 둡니다.
예약 시각을 날짜 행에 되풀이하거나 실제 저장 시각을 대신 표시하지 않으며, 날짜 뒤에
제목·판정·작업 메모를 붙이지 않습니다.

기존 발간호의 온라인 원본은 자동으로 다시 쓰지 않습니다. 화면에서는 이전에 사용한
`.issue-line`, `.issue-bar`, `.folio`와 여러 강조 클래스를 표준 구조로 해석해 같은
읽기 디자인을 적용합니다. 새 템플릿으로 만든 호는 이후 전체 HTML을 고쳐 저장해도
표준 바깥 구조와 공용 클래스가 유지됩니다.

새 발간호 식별자는 `{collection}:{YYYY-MM-DD}:{HH}` 형식을 사용합니다. `HH`에는 예약 발행 시각을 두 자리로 넣으며, 정시 실행을 놓쳐 나중에 발행하더라도 원래 예약 시각을 유지합니다. 정식 주소는 Daily와 Digest의 경우 `/editions/{collection}/issues/{YYYY-MM-DD}/{HH}`, Research의 경우 `/editions/research/brief/issues/{YYYY-MM-DD}/{HH}`입니다. 따라서 같은 날짜의 08시 Daily와 20시 Daily를 서로 다른 발간호로 등록할 수 있습니다. 시간대가 없는 기존 식별자와 주소는 이전 발간호를 읽고 고칠 수 있도록 계속 지원합니다.

## 연결 방식

`Library` 원격 MCP는 페이지를 열지 않은 작업, 새 호 발행과 이미지 업로드를 맡습니다. Library 사이트는 WebMCP를 통해 현재 열린 목록에서 발간호를 찾고, 소유자가 보고 있는 발간호에 수정안을 반영하거나 검토한 수정안을 저장할 수 있습니다.

WebMCP가 없는 브라우저에서도 사이트의 상시 편집과 자동 저장은 그대로 작동합니다. ChatGPT와 Codex가 화면에 반영한 수정안은 자동 저장하지 않고 사용자가 검토한 뒤 별도 도구로 저장합니다. 쓰기 권한은 도구의 표시 여부와 별개로 Sites의 소유자 인증과 서버 API에서 다시 확인합니다.

## 편집과 발행 규칙

본문, 제목, 표지, 삽화, 발행 관문, 연작 점검과 발행 작업 절차의 규칙은 Corpus `library-editorial` Space의 Context Skill이 맡습니다. 표현 원칙은 Sense의 한국어 생성 Skill, 시각 제작 방법은 Sense의 `visual-reference-studio` Skill을 따릅니다. 이 README는 저장소와 서비스 구조만 다룹니다.

화면과 저장 구조에서 오는 조건은 다음과 같습니다. 각 호에는 표지와 본문 삽화를 한 점씩 두며, 표지는 5:7 세로 비율로 업로드하고 발행 화면의 Hype, Star와 Tag 조작이 이미지 위에 놓입니다. 공개 `references`와 발행 metadata는 독자용 항목이므로 Context Skill, Sense Skill, MCP, 내부 경로, 프롬프트, 제작 기록과 작업용 provenance를 넣지 않습니다.

온라인 정본을 저장한 뒤에는 같은 발간호를 다시 읽어 본문, 제목, 날짜와 연속 번호, `references`, 표지 경로가 실제로 바뀌었는지 확인합니다. 저장 요청이 받아들여졌다는 응답만으로 발행이나 수정을 완료했다고 판단하지 않습니다.

사이트 코드를 바꾼 뒤에는 다음 두 검사를 실행합니다.

```bash
npm test
npm --prefix ../../services/library run check
```
