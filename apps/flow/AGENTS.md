# Toolkit Flow 앱 작업 지침

이 앱은 기존 Personal Agent Toolkit의 작업 화면이다. UI Kit 1.4.1 패키지를 직접 사용하고, 공통 버튼·입력·대화상자를 임의 재구현하지 않는다. 이 앱은 에이전트가 만든 작업물을 표시하고, 자료 참조와 변경 확인을 지원한다.

- 사용자 데이터는 앱 소스가 아닌 `TOOLKIT_FLOW_DATA_DIR`에 둔다. 실제 저장본을 테스트 초기값으로 사용하거나 초기화하지 않는다.
- 앱 서비스는 등록된 `TOOLKIT_FLOW_EXEC_HOST`와 `TOOLKIT_FLOW_WORKSPACE_ROOT`가 일치하는 실행 환경에서만 시작한다. Mac에 마운트된 원격 경로에서 Node·Python·빌드·테스트를 실행하지 않는다.
- 브라우저, Host, 에이전트의 실행 환경을 구분한다. Flow에서 Codex나 다른 모델 프로세스를 시작하지 않는다. 에이전트 결과는 작업물 버전과 지정 범위에 묶어 처리한다.
- 원자료의 직접 수정 권한으로 결과 제출을 해석하지 않는다. Host는 등록된 Flow 서비스와 작업공간만 사용한다.
- 기존 작업·작업물 ID, 내용, 보관본과 독립 HTML 파일명을 보존한다. 새 버전 이행은 읽기 검증 후 첫 쓰기에서 수행한다.
- 앱 변경 뒤 `npm run test:workspace`, `npm run test:sites`, 설정한 `TOOLKIT_FLOW_EXPORT_HTML`로 `npm run build`를 Spark에서 실행한다. 호스트나 MCP 변경은 해당 패키지 검사도 수행한다.
- UI에는 실행 로그, 내부 판단·검토 기록이나 장식적 안내를 넣지 않는다.

## UIKit 배치

- 공통 배치 기준은 설치된 UIKit design 스킬의 references/layout.md를 따른다. 실제 규격은 이 앱에 설치된 `node_modules/@personal-agent/ui-kit/README.md`와 `node_modules/@personal-agent/ui-kit/lib/react.css`에서 확인한다.
- 공통 상단바와 메뉴는 `src/work-surface/FlowShell.jsx`의 기존 구성부터 사용한다. 같은 도구를 화면마다 다른 높이와 간격으로 다시 만들지 않는다.
- `src/styles.css`에는 Flow의 콘텐츠 비중, 열 구성과 반응형 배치를 둔다. 버튼과 입력의 내부 규격을 화면 선택자로 덮어쓰지 않는다. 크기는 해당 컴포넌트의 지원 옵션으로 선택한다.
- 작업물의 콘텐츠와 배치 설정은 분리한다. 특정 예시의 열 수나 너비를 모든 작업물의 기본값으로 고정하지 않는다.

## 작업물과 자료

- 작업은 자료를 참조하며 결과를 만들고 수정하는 공간이다. 본문에는 작업물을 표시하고, 원자료는 별도 자료 영역에서 읽는다. 참고 자료 패널에는 현재 작업에 연결한 자료만 표시하고 라이브러리 전체 목록을 섞지 않는다.
- 같은 원본을 자료 ID와 원본 참조로 중복 연결한 경우에는 하나의 항목으로 표시한다. 별도로 정리한 내용은 합치거나 지우지 않는다. 연결 해제는 현재 작업의 참조만 해제하고 자료와 작업물을 보존한다. 원본 연결에 실패해도 해당 항목을 숨기지 않는다.
- 자료 연결은 원본을 참조하는 관계만 만든다. 연결하거나 미리본 자료를 자동으로 작업물 본문에 복사하지 않는다. 자료로 새 작업을 시작할 때도 결과를 미리 채우지 않는다. 보관한 작업물을 명시적으로 복사해 시작하는 동작은 구분한다.
- 에이전트가 내용과 목적에 맞춰 UIKit 기반 HTML의 위계와 배치를 구성한다. 공통 컴포넌트는 에이전트의 제작 수단이지 사용자용 배치 편집기가 아니다. 열 너비, 행 이동, 배치 유형 선택 등을 기본 UI에 추가하지 않는다.
- 이미 만든 HTML은 내부 배치를 유지한 채 표시한다. 구조화 블록으로 다시 옮기는 것을 필수 절차로 삼지 않는다. 기존 블록과 배치 데이터는 보존하며, 내용 수정으로 배치가 바뀌지 않게 한다.

## 세 공간과 저장

- 작업공간은 진행 중인 주 작업물, 라이브러리는 에이전트가 선별한 재사용 자료, 파일은 등록된 실제 폴더를 다룬다. 저장 기간에 따른 의무적인 이동 단계는 만들지 않는다.
- 라이브러리 자료에는 적용 범위와 원본 참조를 유지한다. 예시와 작업별 메모를 개인 기준으로 자동 채택하지 않는다. 기존 Sense, Hypes, Corpus, Journal과 발간 서비스의 정본 및 승인 절차를 유지한다.
- 실제 사용 화면은 Toolkit 웹이다. 주 화면은 WorkCanvas, 목록과 열람은 LibraryBrowser를 사용한다. 로컬 주소는 연결 안내와 미저장 초안 복구에 사용하며, 독립 HTML과 기존 작업물의 열람은 유지한다. 기본 화면에 블록 편집 폼이나 배치 선택기를 다시 붙이지 않는다.
- HTML 작업물은 본문과 불변 자산 참조를 한 버전에 묶는다. 요청한 수정은 같은 ID에 버전 검사 후 반영하며 되돌리기를 지원한다. 기준 버전이 바뀌면 중단한다.
- HTML 스크립트는 중첩된 샌드박스에서만 실행한다. 내부 프레임의 네트워크 이동과 요청을 제한하고, 앱의 계정·쿠키·파일 접근 권한을 넘기지 않는다.
- SQLite 저장 형식 v5는 v1~v4 JSON을 읽고 검증한 뒤 첫 정상 쓰기에서 적용한다. 기존 JSON은 이행 대조용으로 유지한다. v5 전환 후 전체 상태 저장은 거절하며, 이전 JSON으로 되돌리지 않는다. 작업물 본문은 버전별로 조회하고 목록에 이력 본문을 포함하지 않는다. 실제 사용자 저장본 대신 격리된 데이터로 이행과 충돌을 검사한다.
- 자료 조회는 기존 인증 서버의 flow_resource_search/read를 웹과 에이전트가 공유한다. 조회는 원본의 변경, 작업 연결 또는 라이브러리 등록을 뜻하지 않는다. 선택한 본문만 읽고 조회 취소·재시도와 미저장 수정 보존을 지원한다.
- Flow DB는 Host의 기존 백업 설정에 sqlite_paths로 등록한다. 실행 중인 DB와 저널은 일반 복사에서 제외하고 SQLite 안전 복사를 사용한다.
