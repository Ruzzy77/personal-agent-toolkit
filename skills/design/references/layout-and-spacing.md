# 화면 배치와 크기

화면을 새로 만들거나 간격, 크기, 정렬, 반응형 배치를 바꿀 때 적용한다. 기존 디자인 시스템의 컴포넌트와 토큰에서 시작하고, 내용의 관계에 맞춰 조합한다. 문서 본문에는 해당 문서 프로필의 읽기 간격을 유지한다.

## 기준을 정하는 순서

1. 사용 중인 패키지 버전, README, 공개 API와 실제 스타일 정의를 확인한다. 같은 역할의 기존 화면도 함께 본다.
2. 컴포넌트 내부는 제공된 크기와 상태 옵션으로 정한다. 컴포넌트 사이의 간격, 열 구성과 정렬은 부모 배치에서 정한다.
3. 기존 조합으로 해결되지 않을 때만 필요한 범위를 확장한다. 여러 화면에서 쓰는 규격은 공통 컴포넌트에서 고치고, 특정 콘텐츠의 열 폭과 읽는 순서는 해당 화면에서 정한다.

OpenAI의 [UI 가이드](https://developers.openai.com/plugins/concepts/ui-guidelines)는 시스템의 글자, 간격과 아이콘 규격을 유지하는 참고 자료다. ChatGPT 내부에 삽입하는 UI에 관한 제약을 독립 웹 앱 전체의 규칙으로 옮기지 않는다. Geist는 방향이 불분명할 때 필요한 패턴만 참고하며, 다른 시스템의 수치나 스타일을 현재 UIKit 위에 겹쳐 넣지 않는다.

## 간격

- 아이콘과 문구, 같은 조작 묶음, 섹션 내부, 섹션 사이를 구분한다. 서로 관련된 요소의 간격은 묶음 사이보다 좁게 두고, 같은 역할의 묶음에는 같은 규격을 쓴다. [Atlassian 간격 가이드](https://atlassian.design/foundations/spacing)
- 역할에 맞는 배치 컴포넌트와 의미 기반 토큰을 먼저 쓴다. CSS에서는 토큰과 같은 숫자라도 개별 `px` 값으로 다시 적지 않는다. 숫자만 받는 컴포넌트 옵션에는 해당 규격에서 확인한 값을 전달한다.
- 바깥 간격은 부모의 `gap`, 내부 여백은 해당 컨테이너의 `padding`이 맡는다. 같은 경계에 자식의 `margin`을 더해 간격을 중복시키지 않는다.
- 화면과 패널의 안쪽 여백은 각각 한 컨테이너가 맡는다. 중첩된 래퍼마다 패딩을 넣어 내용 폭을 좁히지 않는다.
- 간격이 어색하면 부모 패딩, 형제 간격, 자식 마진과 줄 높이를 나눠 확인한다. 원인을 남겨 둔 채 음수 마진이나 위치 이동으로 맞추지 않는다.
- 토큰만 썼다고 배치가 적절한 것은 아니다. 관련 요소가 떨어져 보이거나 다른 묶음이 붙어 보이면 묶음과 간격의 역할부터 다시 정한다.

## 크기

- 버튼, 입력, 선택, 메뉴는 해당 컴포넌트의 `size`, `variant`, 아이콘 슬롯을 사용한다. 개별 화면에서 내부 패딩, 높이, 글자 크기를 각각 덮어써 새 규격을 만들지 않는다.
- 같은 조작 묶음은 크기 체계를 맞춘다. 종류가 다른 컴포넌트는 같은 `size` 이름만 믿지 말고 실제 높이와 기준선을 확인한다. 주요 행동의 강조와 클릭 영역 확대를 혼동하지 않는다.
- 제목, 본문과 보조 정보는 기존 글자 스타일의 역할로 구분한다. 내용이 길다는 이유로 글자를 축소하거나, 빈 공간을 채우려고 제목과 아이콘을 키우지 않는다.
- 아이콘의 도형 크기와 버튼의 클릭 영역은 따로 확인한다. 클릭하기 어렵다면 도형을 과장하기보다 컴포넌트의 조작 영역을 확보한다.
- WCAG 2.2 AA의 대상 크기는 원칙적으로 24×24 CSS px 이상이며 간격, 인라인 링크 등의 예외가 있다. 터치 조작에는 더 넓은 영역을 고려하되 44×44를 모든 데스크톱 요소에 강제하지 않는다. [대상 크기 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 이미지와 영상은 원래 비율을 보존한다. 잘라 보여 주는 경우에도 사용 목적에 맞는지 확인하며, 비교용 이미지의 주요 부분을 배치를 맞추려고 자르지 않는다.

## 정렬

| 대상 | 정렬 기준 |
| --- | --- |
| 아이콘과 한 줄 조작 문구 | 같은 행의 수직 중앙. 아이콘 슬롯의 크기와 축소 방지 설정을 유지한다. |
| 한 줄 안의 서로 다른 글자 크기 | 글자의 기준선을 맞춘다. 박스 중앙 정렬과 구분한다. |
| 여러 줄 설명이 있는 항목과 보조 조작 | 내용의 시작선을 맞춘다. 설명이 늘어날 때 조작이 아래로 밀리지 않게 한다. |
| 입력과 실행 버튼 | 라벨이 아닌 입력 영역을 맞춘다. 오류와 도움말이 늘어나는 상태도 확인한다. |
| 같은 목록의 이름, 상태와 조작 | 반복되는 열과 시작선을 공유한다. 행마다 독립적인 임의 폭을 주지 않는다. |

텍스트가 어긋나면 폰트와 줄 높이, SVG의 여백, 부모 정렬을 먼저 확인한다. 시각적 보정이 꼭 필요하면 해당 공통 컴포넌트에서 최소한으로 적용한다. 개별 화면의 `translateY`나 빈 요소로 맞추지 않는다.

## 폭과 반응형 배치

- 주 콘텐츠와 보조 콘텐츠의 비중, 최소 읽기 폭을 먼저 정한다. 중요도와 내용 길이가 다른 영역을 같은 폭의 카드로 강제하지 않는다.
- 가능한 너비는 화면 폭에서 바깥 여백과 열 사이 간격을 뺀 값으로 판단한다. 고정 폭은 도구 영역처럼 역할상 필요한 곳에 한정하고, 본문은 가용 공간에 맞춰 늘어나게 한다.
- Flex와 Grid의 줄어들어야 할 자식에는 `min-width:0`을 적용한다. 가변 열에는 필요에 따라 `minmax(0,1fr)`을 쓴다. 이름과 본문의 줄바꿈, 말줄임 조건은 각각 정한다.
- 내용이 들어가지 않으면 열을 줄이거나 줄바꿈하고, 보조 조작을 기존 메뉴로 옮긴다. 글자와 조작 영역을 일괄 축소하거나 기능을 없애서 맞추지 않는다.
- breakpoint는 기존 규칙을 우선 사용한다. 새 전환점이 필요하면 실제 콘텐츠가 겹치거나 읽기 폭을 잃는 지점에서 정하고, 전환 직전과 직후를 확인한다.
- 메뉴와 팝오버는 컴포넌트의 정렬, 너비와 화면 경계 처리 옵션을 사용한다. 긴 문구, 아이콘, 선택 표시가 함께 들어가는지 확인한다. 스크린샷의 좌표를 고정 위치로 옮기지 않는다.
- 시각적 순서와 DOM의 읽기 순서를 유지한다. 반응형 전환으로 조작이 이동하거나 닫힐 때 포커스가 사라지지 않게 한다. Geist의 [Grid 예시](https://vercel.com/geist/grid)도 반응형 구성과 읽기 순서를 참고하는 용도로만 쓴다.

## UI Kit을 사용하는 경우

선택한 `@personal-agent/ui-kit` 패키지의 README와 스타일 정의에서 다음 조합을 확인한다. 실제 값은 설치된 릴리스가 정하며, 이 가이드에 별도 수치표를 유지하지 않는다.

| 필요한 배치 | 우선 사용할 조합 |
| --- | --- |
| 같은 행의 조작 묶음 | `.su-row`, `--su-control-gap` |
| 같은 영역의 세로 묶음 | `.su-stack`, `--su-stack-gap` |
| 독립된 섹션 사이 | `.su-stack[data-gap="section"]`, `--su-section-gap` |
| 제목과 내용 | `.su-section` |
| 제목 또는 필터와 관련 조작 | `.su-toolbar` |
| 입력이나 동등한 콘텐츠의 열 | `.su-grid`, 필요한 최소 읽기 폭에 맞춘 `--su-column-min` |
| 실제 경계가 필요한 패널 | `.su-panel`, `--su-panel-padding` |
| 일반 작업 화면의 바깥 폭과 여백 | `.su-workspace`, `--su-page-gutter` |

`.su-row`의 기본은 수직 중앙 정렬이며 `data-align="start"`와 `"end"`를 지원한다. `.su-toolbar`는 아래쪽 정렬과 줄바꿈을 제공하므로, 한 줄 상단바의 중앙 정렬과 구분한다. 해당 릴리스가 제공하는 속성만 사용한다.

`.su-grid`는 동등한 열을 구성할 때 쓴다. 주 콘텐츠와 보조 설명처럼 비중이 다르면 화면의 Grid 배치에서 열 비율을 정하되 간격은 공통 토큰을 쓴다. `.su-workspace`의 일반 작업 화면 폭을 표, 도식, 편집 캔버스 모두에 강제하지 않는다.

React의 공식 컴포넌트 내부에 `.su-btn` 같은 HTML 어댑터 스타일을 겹치지 않는다. Lucide 아이콘은 공식 슬롯에서 `1em`을 사용하며, 버튼마다 별도 크기를 만들지 않는다. 메뉴의 아이콘, 항목명, 현재 선택 표시는 각각의 열을 유지한다.

예를 들어 제목과 관련 도구, 본문은 다음처럼 조합한다. 기존 컨테이너가 같은 여백을 맡고 있다면 바깥 래퍼를 중복 추가하지 않는다.

```jsx
<section className="su-section">
  <div className="su-toolbar">
    <h2>자료 목록</h2>
    <div className="su-row">{actions}</div>
  </div>
  {content}
</section>
```

## 구현 후 확인

변경한 영역에서 대표적인 큰 화면과 작은 화면, 관련 breakpoint의 양쪽을 확인한다. 실제 한국어 문구와 긴 이름을 사용하고, 변경과 관련된 메뉴 열림, 오류, 선택 상태를 포함한다.

- 눈으로 시작선, 간격의 위계와 콘텐츠 비중을 확인한다. 필요한 곳은 computed style과 요소의 실제 영역을 읽어 크기, 여백과 클릭 영역을 구분한다.
- 잘림과 가로 넘침을 `overflow:hidden`으로 감추지 않는다. 통상적인 세로 읽기 화면은 320 CSS px에서도 내용과 기능을 유지한다. 표와 도식처럼 2차원 배치가 필요한 부분은 그 영역 안에서 탐색할 수 있게 한다. [Reflow 기준](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- 글자 확대와 간격 변경으로 내용이 사라지지 않는지 확인한다. WCAG의 줄 높이 1.5배, 문단 간격 2배, 자간 0.12em, 단어 간격 0.16em은 사용자가 간격을 늘려도 내용과 기능이 유지되는지 확인하기 위한 값이며, 화면의 기본 글자 스타일을 이 값으로 바꾸라는 뜻이 아니다. [글자 간격 기준](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)
- 키보드 초점이 보이고, 메뉴 선택과 닫기, 반응형 전환 뒤에도 실제 조작을 이어갈 수 있는지 확인한다.

새 CSS 규칙을 추가하기 전에 같은 역할의 기존 클래스와 토큰을 찾는다. 패키지 내부 규격의 문제인지 부모 배치의 문제인지 구분해 해당 위치를 고친다. 확인 결과를 제품 화면에 안내문이나 관리 항목으로 덧붙이지 않는다.
