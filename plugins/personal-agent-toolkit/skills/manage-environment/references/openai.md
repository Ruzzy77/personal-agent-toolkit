# OpenAI and the instruction workbench

For local Codex state, read the requested setting, the host's supported configuration and the tools exposed to the task. Stored defaults, installed files and instructions actually supplied to a running task are separate observations. Do not edit app bundles, caches or task records to force an apparent configuration change.

If a supplied Skill locator points to a removed package version, inspect the current installation metadata and resolve that same Skill in the installed package. Do not recreate the old directory, treat a stale locator as proof that no guidance was delivered, or add startup retrieval to compensate. Use the host's supported update path when an update is requested; verify fresh-session discovery separately from the installed bytes.

For product facts, support, pricing, API contracts or a requested model migration, use the current official-documentation tools, or official OpenAI web sources when those tools are unavailable. Verify precise claims in the relevant original documentation rather than search snippets. Preserve the user's selected model and purpose; do not turn a prompt revision into an unrequested evaluation program or deployment. Local observations establish local behavior, not a universal product guarantee.

When the user asks to browse or edit instructions visually, locate the existing workbench through current project or host registration. Preserve its open tab and unsaved drafts. It may browse authorized canonical content and accept a user's direct save; a separate conversation request is not required for a save the user performs in the UI. Conversational changes may continue through the canonical tools without opening the workbench.

Use real identity, canonical version and the submitted draft for a save. Re-read the stored result before reporting it as saved, and preserve a newer draft if an older save finishes later. A saved base document is available to a new run only after the host's managed projection and configuration are updated. Saving remote guidance alone does not prove that a running model is using it.
