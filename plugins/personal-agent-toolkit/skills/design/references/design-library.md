# 선택형 디자인 참고 라이브러리

이 참고 묶음은 기존 디자인 시스템을 대신하는 규칙집이 아니다. 사용자가 시각 방향을
탐색하거나, 현재 프로젝트만으로 적절한 구성 원리를 정하기 어렵거나, 형식에 맞는 예시
자산이 실제로 도움이 될 때만 사용한다.

시각적 비교가 필요하면 소유자 전용
[Design Reference Library Site](https://personal-material-index.ruzzy.chatgpt.site)를 열 수 있다.
에이전트에서는 현재 연결에 노출된 Design 도구로 같은 개인 라이브러리를 읽는다.

## 우선순위

1. 현재 프로젝트의 브랜드, 토큰, 컴포넌트와 콘텐츠 계약
2. 사용자가 직접 고른 참고 자료와 명시한 방향
3. 라이브러리의 범용 패턴
4. 이름이 붙은 선택적 레시피
5. 레시피에 포함된 템플릿과 예시 자산

상위 기준과 충돌하는 레시피의 색상, 글꼴이나 판면은 적용하지 않는다. 레시피 이름을
결과물의 공식 디자인 시스템처럼 소개하지 않는다.

## 찾는 방법

1. `design_list_recipes`로 결과물의 형식과 상태에 맞는 후보를 좁힌다.
2. 연결된 레시피를 한 가지 정답으로 고르지 말고, 실제 선택에 도움이 되는 경우에만
   후보 1–3개를 비교한다. 각 후보에는 맞는 이유와 충돌하거나 부족한 점을 함께 본다.
3. `design_read_recipe`로 고른 레시피의 원칙과 파일 목록을 읽는다.
4. HTML 틀, CSS와 이미지가 실제 제작에 필요할 때만 `design_read_asset`으로 해당 파일 하나를
   읽어 복사하거나 변형한다. 내용 순서와 문구는 현재 과업에 맞게 다시 구성한다.

`format_support`의 뜻은 다음과 같다.

- `guidance`: 구성 원칙만 제공한다.
- `assets`: 적용할 수 있는 CSS, 템플릿이나 예시 자산이 있다.
- `verified`: 묶음의 대표 예시가 해당 형식에서 확인되었다.

제공 수준보다 넓게 검증되었다고 말하지 않는다. `provenance.references`가 있는 레시피는
링크된 자료에서 가져온 원리와 라이브러리 자체 표현을 구분한다.

## 저장 경계

개인 레시피와 자산은 Design 서비스에만 저장하고 plugin이나 현재 프로젝트에 자동으로 복제하지
않는다. 새 레시피나 파일을 보관하라는 명시적 요청이 있을 때만 쓰기 도구를 사용하며, 현재
revision을 읽은 뒤 갱신한다. 연결이 없으면 개인 자산을 추정하거나 공개 예시로 대체하지 않고
현재 프로젝트의 자료만으로 작업을 이어간다.
