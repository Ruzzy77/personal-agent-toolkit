# 선택형 디자인 참고 라이브러리

이 참고 묶음은 기존 디자인 시스템을 대신하는 규칙집이 아니다. 사용자가 시각 방향을
탐색하거나, 현재 프로젝트만으로 적절한 구성 원리를 정하기 어렵거나, 형식에 맞는 예시
자산이 실제로 도움이 될 때만 사용한다.

시각적 비교가 필요하면 [Design Reference Library Site](https://personal-material-index.ruzzy.chatgpt.site)를
열 수 있다. Site와 이 오프라인 묶음은 같은 공개 카탈로그를 사용한다. Site에 접근할 수 없거나
브라우저를 쓸 필요가 없으면 아래 파일만으로 작업을 이어간다.

## 우선순위

1. 현재 프로젝트의 브랜드, 토큰, 컴포넌트와 콘텐츠 계약
2. 사용자가 직접 고른 참고 자료와 명시한 방향
3. 라이브러리의 범용 패턴
4. 이름이 붙은 선택적 레시피
5. 레시피에 포함된 템플릿과 예시 자산

상위 기준과 충돌하는 레시피의 색상, 글꼴이나 판면은 적용하지 않는다. 레시피 이름을
결과물의 공식 디자인 시스템처럼 소개하지 않는다.

## 찾는 방법

1. `../assets/design-library/catalog.json`에서 결과물의 형식, 내용과 필요한 기능에 맞는
   패턴을 먼저 찾는다.
2. 연결된 레시피를 한 가지 정답으로 고르지 말고, 실제 선택에 도움이 되는 경우에만
   후보 1–3개를 비교한다. 각 후보에는 맞는 이유와 충돌하거나 부족한 점을 함께 본다.
3. 고른 레시피의 `recipes/<id>/formats.json`, `DESIGN.md`와 `README.md` 중 현재 형식에
   필요한 자료만 읽는다.
4. HTML 틀, CSS와 이미지가 실제 결과물 제작에 필요할 때만 해당 파일을 복사하거나
   변형한다. 내용 순서와 문구는 현재 과업에 맞게 다시 구성한다.

`format_support`의 뜻은 다음과 같다.

- `guidance`: 구성 원칙만 제공한다.
- `assets`: 적용할 수 있는 CSS, 템플릿이나 예시 자산이 있다.
- `verified`: 묶음의 대표 예시가 해당 형식에서 확인되었다.

제공 수준보다 넓게 검증되었다고 말하지 않는다. `provenance.references`가 있는 레시피는
링크된 자료에서 가져온 원리와 라이브러리 자체 표현을 구분한다.

## 묶음 경계

아래 경로는 이 참고 파일을 기준으로 한다.

- `../assets/design-library/catalog.json`: 패턴, 공개 레시피와 콘텐츠 해시
- `../assets/design-library/patterns.json`: 스타일에 종속되지 않는 구성 원리와 점검 항목
- `../assets/design-library/recipes/`: 공개 레시피의 문서, 형식 규칙과 자산
- `../assets/design-library/LICENSE`: 묶음 라이선스

묶음은 오프라인에서 완결된다. 별도 사이트, 원격 MCP나 계정 연결을 전제로 하지 않으며,
프로젝트 전용 확장과 사용자 자료는 포함하지 않는다.
