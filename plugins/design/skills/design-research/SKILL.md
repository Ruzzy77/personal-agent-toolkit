# Design Research

사용자 조사를 설계하거나 수집된 자료를 종합해 제품 결정에 필요한 관찰과 한계를
분명하게 만든다. 아직 참가자를 만나거나 자료를 수집하지 않았다면 조사를 수행했다고
표현하지 않는다.

## 작업 방식 선택

- **조사 설계:** 앞으로 얻어야 할 자료, 참가자, 방법과 진행 자료를 정한다.
- **자료 종합:** 이미 있는 원자료에서 반복되는 행동, 문제와 반대 사례를 찾는다.

두 방식이 이어지는 작업이라도 현재 요청에 필요한 범위만 수행한다. 표본 수, 산출물
형식이나 분석 단계를 고정된 모범 답안으로 강제하지 않는다.

## 조사 설계

먼저 어떤 결정을 내려야 하는지, 현재 무엇을 알고 모르는지, 누구의 어떤 행동과 맥락이
그 결정에 필요한지 정한다. 결과를 누가 언제 어떤 한계 안에서 사용할지도 확인한다.

방법은 질문에 맞게 고른다. 인터뷰는 동기와 맥락, 사용성 시험은 특정 흐름에서 생기는
문제, 설문은 정의된 모집단의 분포, 카드 분류는 정보 구조, 일기 연구는 시간에 따른
행동을 이해하는 데 적합할 수 있다. A/B 시험은 미리 정한 지표와 해석 가능한 표본이
있을 때 사용한다.

표본 수와 기간은 발견하려는 문제의 빈도와 위험, 필요한 사용자 다양성, 모집 가능성과
분석 방법에 따라 정한다. 근거 없이 익숙한 숫자를 제시하지 않는다.

참가자의 포함·제외 기준과 필요한 다양성을 밝히고, 자발적 동의, 녹음·보관·공유 범위,
중단하거나 답하지 않을 권리와 접근성 편의를 다룬다. 실제 법률과 조직 정책이 없으면
보존 기간이나 보상액을 만들지 않는다. 민감한 정보는 결정에 필요한 범위만 수집한다.

질문은 현재 행동과 실제 사례에서 시작한다. 답을 유도하거나 두 가지를 한 번에 묻지
않고, 가설을 확인하는 질문과 새로운 사실을 찾는 질문을 구분한다. 프로토타입은 선호만
묻지 말고 참가자가 과업을 수행하는 과정을 관찰한다.

필요한 결과에는 연구 질문과 성공 조건, 참가자 기준과 모집 문항, 동의와 세션 안내,
중립적인 질문과 후속 질문, 과업 시나리오, 관찰·기록 방법, 분석 계획과 알려진 한계를
포함한다.

## 자료 종합

자료 종류, 조사 질문, 수집 방법, 참가자나 응답 범위, 날짜와 제품 버전을 먼저 파악한다.
누락·중복·개인정보와 서로 비교할 수 없는 자료가 섞였는지 확인한다. 원자료가 여러
파일이나 서비스에 나뉘면 각 관찰을 다시 찾을 수 있게 연결하고, 이름이 필요하지 않은
결과에서는 식별 정보를 익명화한다.

관찰 단위를 먼저 기록한 뒤 관련 항목을 묶는다. 빈도가 높다는 이유만으로 영향이 크다고
보지 않고, 드물더라도 과업을 막거나 특정 사용자에게 심각한 문제인지 확인한다. 각 주요
주제에는 가능한 범위에서 다음을 연결한다.

- 해당 참가자나 응답 수와 전체 자료 범위
- 실제 행동 또는 원문과 대조한 짧은 인용
- 반대 사례와 맞지 않는 자료
- 발생 조건과 영향을 받는 과업
- 해석의 확실성과 가능한 다른 설명

직접 인용은 의미를 바꾸도록 다듬거나 여러 발화를 하나로 합치지 않는다. 참가자 수,
비율과 사용자 집단을 만들지 않고, 작은 정성 표본을 전체 사용자의 고정된 집단이나
규모로 일반화하지 않는다.

## 결과

관찰, 해석, 제품 제안과 아직 답하지 못한 질문을 구분한다. 주요 주제와 자료 범위,
의사결정에 영향을 주는 한계, 모순되는 신호와 후속 조사를 필요한 만큼 제시한다.
영향과 개발 비용은 연구 자료만으로 확정하지 않고 사업 목표와 구현 자료가 있을 때
별도의 제품 판단으로 다룬다.
