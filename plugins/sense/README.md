# Sense

Sense는 여러 AI가 사용자와 일할 때 참고하는 하나의 비공개 작업 프로필을 관리한다.
여러 작업에 적용되는 목적·책임·협업 방식과 선택 기준만 남긴다. 프로젝트의 자료와 결과는
각 프로젝트가 소유하고, 한 업무의 원자료와 이어 갈 맥락은 Corpus가 맡는다. Hypes의
잠정적인 사용자 해석도 Sense에 복제하지 않는다.

프로필은 플러그인 설치 폴더가 아닌 macOS의 비공개 저장소에 있으므로 플러그인을 바꿔도
유지된다. 현재 요청과 현재 자료가 Sense보다 우선한다. 중요한 해석이나 선택에 관련 내용이
있을 때만 읽고, 단순 조회나 한 단계 실행에는 사용하지 않는다.

## 도구

| 도구 | 역할 |
| --- | --- |
| `sense_read` | 색인 또는 필요한 항목만 읽음 |
| `sense_overview` | 민감 항목과 원자료 위치를 뺀 전체 검토 화면을 표시함 |
| `sense_preview_revision` | 최종 변경 묶음의 충돌과 차이를 저장 전에 확인함 |
| `sense_revise_batch` | 관련 변경을 한 개정으로 함께 저장함 |
| `sense_control` | 전체 점검·내보내기와 삭제 범위를 확인함 |
| `sense_status` | 현재 개정, 저장 상태와 실행 버전을 확인함 |

여러 항목을 고칠 때에는 최종 문안을 모아 한 번 미리 보고 한 번 저장한다. 같은 항목의
변경이 여러 개면 마지막 최종안만 쓴다. 수정하려는 항목이 읽은 뒤 달라졌으면 전체 저장을
중단하고, 관련 없는 항목만 달라졌다면 대상 항목의 해시가 같은 동안 계속할 수 있다.

삭제와 프로필 활성화는 모델이 전달한 확인 문구로 승인하지 않는다. 정확한 대상과 현재
해시를 보여 주는 로컬 제어 경로에서만 실행한다.

## 저장 위치

기본 위치는 다음과 같다.

```text
~/Library/Application Support/Sense/
├── sense.sqlite3
└── runtime.lock
```

디렉터리는 `0700`, 데이터베이스와 잠금 파일은 `0600`으로 유지한다. 현재 프로필과 최근
12개 개정본만 저장하며 대화 전문, 작업 로그와 원자료 본문은 저장하지 않는다.

## 실행

처음 실행하거나 의존성이 바뀌었을 때만 환경을 맞춘다.

```sh
uv sync
./bin/sense status
```

이 폴더가 실행 코드, 스킬, UI와 Codex·Claude manifest를 함께 보관하는 정본이다.
marketplace도 이 폴더를 직접 설치하므로 별도 패키지 생성 단계가 없다.

보관 중인 개정본은 새 기록을 만들지 않는 로컬 명령으로 확인한다.

```sh
./bin/sense history
./bin/sense history --from-revision 18 --to-revision 19
```

개인용 Chat 연결이 필요하면 공용 Personal Agent Tunnel이 이 로컬 MCP를 그대로 연결한다.
Sense가 별도의 원격 데이터베이스, 이관 형식이나 호스팅 서버를 소유하지 않는다.

## 개발 범위

정본은 이 plugin 폴더의 `src/sense/`, `skills/`, `bin/`과 root manifest다. 발간 사이트,
연구 브리프 렌더러, 평가 corpus와 과거 결과는 Sense 제품에 포함하지 않는다.

TDD, 전체 회귀와 패키지 재검증을 일상 개발의 기본 절차로 사용하지 않는다. 변경한 실행
경로를 직접 확인하고, 데이터 손실·저장 권한·동시 수정처럼 실제 사용자 상태를 해칠 수
있는 경계만 작은 테스트로 남긴다. 새 사례가 기존 테스트와 같은 경계를 확인하면 기존
사례에 합치거나 중복 사례를 지운다. 실제 배포에서는 plugin 시작과 기본 도구만 확인한다.
