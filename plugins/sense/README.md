# Sense

Sense는 여러 AI가 사용자와 일할 때 참고하는 하나의 비공개 작업 프로필을 관리한다. 여러 작업에
적용되는 목적·책임·협업 방식과 선택 기준만 남긴다. 프로젝트 자료와 결과는 각 프로젝트가
소유하고, 한 업무의 원자료와 이어 갈 맥락은 Corpus가 맡는다. Hypes의 잠정적인 사용자 해석도
Sense에 복제하지 않는다.

현재 요청과 현재 자료가 Sense보다 우선한다. 중요한 해석이나 선택에 관련 내용이 있을 때만
읽고, 단순 조회나 한 단계 실행에는 사용하지 않는다.

## 도구

| 도구 | 역할 |
| --- | --- |
| `sense_read` | 색인 또는 필요한 항목만 읽음 |
| `sense_overview` | 민감 항목을 제외한 현재 프로필을 검토 화면에 표시함 |
| `sense_revise` | 최종 항목 교체를 한 트랜잭션으로 저장함 |

Sense를 고칠 때에는 관련 항목을 읽어 받은 `section_sha256`와 최종 항목 전체를 한 번 전달한다.
대상 항목이 그사이 달라졌으면 요청을 중단한다. 같은 최종 상태를 다시 보내면 아무것도
쓰지 않는다. 별도 미리보기·개정 번호·멱등성 키·과거 개정본은 사용하지 않는다.

에이전트가 문안을 작성했거나 여러 항목을 함께 바꿀 때에는 Chat에서 최종 문안을 먼저 보여 준다.
민감 항목의 저장과 영구 삭제는 로컬 명령에서 처리한다.

## 저장 위치

기본 위치는 다음과 같다.

```text
~/Library/Application Support/Sense/
├── sense.sqlite3
└── runtime.lock
```

디렉터리는 `0700`, 데이터베이스와 잠금 파일은 `0600`으로 유지한다. 데이터베이스에는 현재
프로필 하나만 저장한다. 대화 전문, 작업 로그, 원자료, 출처 위치와 과거 프로필은 저장하지 않는다.
이전 스키마를 처음 열면 현재 활성 프로필만 새 형식으로 옮기고 과거 개정·재실행 기록과 구형
필드는 삭제한다.

## 로컬 관리

```sh
uv sync
./bin/sense read --view full
./bin/sense status
```

프로필을 처음 가져오거나 기존 프로필을 교체할 수 있습니다.

```sh
./bin/sense import-profile --input profile.json
./bin/sense import-profile --input profile.json --replace --confirm-replace
```

항목 또는 전체 데이터의 영구 삭제에는 로컬 확인 플래그가 필요합니다.
