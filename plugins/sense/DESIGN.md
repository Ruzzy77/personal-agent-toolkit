# Sense 설계

Sense는 여러 작업에서 계속 적용되는 사용자 통제형 작업 프로필 하나를 소유자별 원격 저장층에
보관한다. Codex, Claude와 ChatGPT는 플랫폼별 사본이 아니라 같은 현재 프로필을 읽는다. 로컬
SQLite 구현은 [`engines/sense`](../../engines/sense/README.md)에 둔 개발·최초 이관용 별도 경계다.

## 소유 경계

| 대상 | 소유자 |
| --- | --- |
| 여러 작업에 적용되는 목적, 책임, 협업 방식과 선택 기준 | Sense |
| Sense 항목과 이어지는 범용 작업 방법 | Sense Section Skill |
| 한 업무의 원자료, 질문, 관계와 이어 갈 맥락 | Corpus |
| 에이전트의 수정 가능한 사용자 관계 모델 | Hypes |
| 프로젝트 사실, 코드와 산출물 | 각 프로젝트 |
| 대화의 자연스러운 연속성 | 각 플랫폼의 메모리 기능 |

완료 작업과 대화를 시간순으로 쌓지 않는다. 다음 선택을 바꾸는 내용이 생기면 관련 항목의
현재 문안을 교체한다.

## 프로필

```json
{
  "schema_version": 2,
  "sections": [
    {
      "id": "questions-and-choices",
      "purpose": "이 항목을 참고할 이유",
      "text": "현재 적용할 내용",
      "origins": ["user_set", "learned_from_results"],
      "sensitivity": "ordinary"
    }
  ]
}
```

프로필에는 현재 지침에 필요한 다섯 필드만 둔다. 출처 위치, 원자료 해시, 적용 목록, 검토 조건과
고정 제품 정책은 저장하지 않는다. 민감 항목은 일반 색인과 검토 화면에서 제외한다.

## Section Skill

각 프로필 항목에는 사용자가 반영한 `SKILL.md`를 하나까지 연결할 수 있다. 항목 본문은 여러
맥락에 이어지는 의도와 판단 방향을 담고, Section Skill은 그 방향을 실제 작업에 적용하는 방법을
담는다. Skill은 자료나 사실의 출처를 대신하지 않는다.

Section Skill은 프로필 JSON에 넣지 않고 원격 저장층에서 소유자와 항목 ID로 분리해 보관한다.
색인은 이름, 설명과 버전만 보여 주며, 관련 항목을 열 때 전체 지침을 함께 반환한다. 한 항목에
여러 Skill을 두는 목록 구조와 별도 Skill 조회 도구는 현재 범위에 만들지 않는다. 로컬 개발·이관
구현은 같은 논리 구조를 `sections/<section-id>/skill/SKILL.md`로 표현한다.

## 저장과 수정

운영 정본은 Personal Agent Context service의 소유자별 D1 행과 Section Skill 레코드다. 일반
항목 수정은 현재 section digest를 대조한 뒤 한 D1 트랜잭션으로 프로필을 교체하며, 일반 Section
Skill도 현재 버전을 대조해 한 레코드를 교체한다.

로컬 개발·이관 구현의 기본 저장 위치는 `~/Library/Application Support/Sense/`다. 디렉터리는
`0700`, 데이터베이스와 잠금 파일은 `0600`으로 유지한다. SQLite에는 `current_profile` 한 행만
저장한다. 로컬 변경은 원격 정본으로 자동 전파되지 않는다.

수정 요청은 다음 세 값으로 구성한다.

- `section_id`
- 읽을 때 받은 `previous_section_sha256`
- 교체할 `new_section`

관련 항목을 현재 저장층의 한 트랜잭션에서 대조한 뒤 함께 저장한다. 항목 하나라도 달라졌으면
아무것도 쓰지 않는다. 현재 내용이 최종안과 이미 같으면 자연스러운 무변경 결과를 반환한다. 전체
개정 번호, 도구 미리보기, 재실행 영수증과 과거 개정본은 두지 않는다.

이전 스키마는 한 번만 현재 형식으로 옮긴다. 구형 항목 ID를 정식 ID로 바꾸고 현재 활성 프로필에서
필요한 필드만 남긴 뒤, 개정 이력·재실행 기록과 구형 테이블을 삭제한다. 이후에는 구형 이름을
해석하는 호환 계층을 유지하지 않는다.

## MCP와 로컬 제어

도구의 입력 스키마는 중첩 필드를 참조 없이 직접 포함한다. 클라이언트가 `$defs`를 노출하지
않아도 교체 항목의 필드와 제약을 확인할 수 있다. 실행 시 입력 검증과 저장 규칙은 같은 모델을
사용하며, 출력 스키마는 바꾸지 않는다.

공개 도구는 `sense_read`, `sense_overview`, `sense_revise`, `sense_skill_revise` 네 개다. `sense_read` 색인은 연결된
Section Skill의 소개를 포함하고, 항목 읽기는 전체 지침을 포함한다. 일반 항목은 사용자가 저장을
요청한 최종 문안만 수정한다. 에이전트가 작성한 문안과 여러 항목 변경은 도구 미리보기 대신 Chat에서
최종 내용을 검토한다.

일반 Section Skill은 사용자가 명시적으로 요청한 경우 현재 `version`과 전체 교체안을 대조해 Chat에서
수정한다. 동일한 최종안은 무변경으로 끝나며 충돌하면 기존 Skill을 보존한다. 민감 항목 수정,
민감 Section Skill의 원격 저장, Skill 제거, 항목 삭제와 전체 데이터 삭제는 공개 원격 MCP에
노출하지 않는다. 로컬 CLI의 확인 플래그는 로컬 개발·이관 저장소에만 적용되므로, 그 결과를 원격
정본의 변경으로 간주하지 않는다. 운영 정본의 제거는 소유자가 통제하는 서비스 운영 경계에서만
수행한다.

## 검토 화면

`sense_overview`는 일반 항목의 제목, 목적, 본문, 기원과 연결된 Section Skill을 표시한다. 민감한
본문과 내부 변경 토큰은 표시하지 않는다. 최근 변경과 출처 목록은 저장하지 않으므로 화면에도 만들지
않는다.
