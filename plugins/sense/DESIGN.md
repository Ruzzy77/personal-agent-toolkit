# Sense 설계

Sense는 여러 작업에서 계속 적용되는 사용자 통제형 작업 프로필 하나를 로컬에 보관한다. Codex와
Claude는 플랫폼별 사본이 아니라 같은 현재 프로필을 읽는다.

## 소유 경계

| 대상 | 소유자 |
| --- | --- |
| 여러 작업에 적용되는 목적, 책임, 협업 방식과 선택 기준 | Sense |
| 한 업무의 원자료, 질문, 관계와 이어 갈 맥락 | Corpus |
| 에이전트의 수정 가능한 사용자 관계 모델 | Hypes |
| 프로젝트 사실, 코드와 산출물 | 각 프로젝트 |
| 대화의 자연스러운 연속성 | 각 플랫폼의 메모리 기능 |

완료 작업과 대화를 시간순으로 쌓지 않는다. 다음 선택을 바꾸는 내용이 확인됐을 때 관련 항목의
현재 문안을 교체한다.

## 프로필

```json
{
  "schema_version": 2,
  "sections": [
    {
      "id": "questions-and-choices",
      "purpose": "이 항목을 참고할 이유",
      "text": "현재 적용할 내용",
      "origins": ["user_set", "learned_from_results"],
      "sensitivity": "ordinary"
    }
  ]
}
```

프로필에는 현재 지침에 필요한 다섯 필드만 둔다. 출처 위치, 원자료 해시, 적용 목록, 검토 조건과
고정 제품 정책은 저장하지 않는다. 민감 항목은 일반 색인과 검토 화면에서 제외한다.

## 저장과 수정

기본 저장 위치는 `~/Library/Application Support/Sense/`다. 디렉터리는 `0700`, 데이터베이스와
잠금 파일은 `0600`으로 유지한다. SQLite에는 `current_profile` 한 행만 저장한다.

수정 요청은 다음 세 값으로 구성한다.

- `section_id`
- 읽을 때 받은 `previous_section_sha256`
- 교체할 `new_section`

관련 항목을 한 SQLite 트랜잭션에서 모두 확인한 뒤 함께 저장한다. 항목 하나라도 달라졌으면 아무것도
쓰지 않는다. 현재 내용이 최종안과 이미 같으면 자연스러운 무변경 결과를 반환한다. 전체 개정 번호,
도구 미리보기, 재실행 영수증과 과거 개정본은 두지 않는다.

이전 스키마는 한 번만 현재 형식으로 옮긴다. 구형 항목 ID를 정식 ID로 바꾸고 현재 활성 프로필에서
필요한 필드만 남긴 뒤, 개정 이력·재실행 기록과 구형 테이블을 삭제한다. 이후에는 구형 이름을
해석하는 호환 계층을 유지하지 않는다.

## MCP와 로컬 제어

공개 도구는 `sense_read`, `sense_overview`, `sense_revise` 세 개다. 일반 항목은 사용자가 저장을
요청한 최종 문안만 수정한다. 에이전트가 작성한 문안과 여러 항목 변경은 도구 미리보기 대신 Chat에서
최종 내용을 검토한다.

민감 항목 수정, 항목 삭제, 전체 데이터 삭제와 기존 프로필 교체는 로컬 CLI에서만 실행한다. 삭제는
별도 이력이나 복구 프로토콜을 만들지 않고 명시적 확인 플래그로 보호한다.

## 검토 화면

`sense_overview`는 일반 항목의 제목, 목적, 본문과 기원만 표시한다. 민감한 본문과 내부 변경 토큰은
표시하지 않는다. 최근 변경과 출처 목록은 저장하지 않으므로 화면에도 만들지 않는다.

## 개발 판단

이 plugin 폴더가 실행 코드, 스킬, 읽기 전용 UI, launcher와 manifest를 함께 보관하는 정본이다.
제품 동작보다 큰 검증·배포 구조를 두지 않는다. 실제 사용자 데이터의 권한, 원자적 저장, 섹션 충돌과
영구 삭제 확인은 유지한다.
