# Sense 개발 원칙

Sense의 기능보다 큰 테스트·검증·배포 구조를 만들지 않는다.

- 필요한 동작은 기존 경로에 작게 구현하고, 수정한 부분의 기본 검사와 직접 관련된 테스트 한두 개만 확인한다.
- 사례마다 회귀 테스트를 추가하지 않는다. 데이터 손실, 저장 경계 또는 재현된 핵심 장애를 기존 사례로 확인할 수 없을 때만 추가하고, 중복 사례는 함께 지운다.
- 평가 harness, golden 결과, 전용 검증 script와 전체 조합 검사를 기본 개발 절차로 두지 않는다.
- 같은 기능의 단일·일괄·legacy 도구를 함께 유지하지 않는다. 정본 도구 하나를 고치고 오래된 표면은 제거한다.
- 로컬 제품에 쓰지 않는 원격 실행, 이관, 배포 계층은 미리 만들지 않는다.
- 이 plugin 폴더가 소스이자 설치 경로다. 별도 배포 사본, package builder와 생성 version 파일을 두지 않는다.
- 실제 사용자 데이터의 권한, 원자적 저장, 충돌 방지와 삭제 확인은 유지한다.
