# Hypes

Hypes는 에이전트가 현재 사용자를 이해하는 비공개 관계 모델이다. 저장된 관계는 다음 요청을
해석하거나 선택할 때 필요한 범위에서만 사용하며, 현재 사용자의 말이 항상 우선한다. Hypes는
사용자 프로필, 지침 저장소나 대화 기록이 아니다.

## 사용 조건

Hypes는 저장된 관계가 현재 해석·설명·질문·선택을 바꿀 수 있거나, 사용자가 현재 모델을 묻거나,
이번 상호작용으로 나중에도 유용할 관계가 실제로 달라졌을 때 사용한다. 관계없는 조회, 단순 변환과
현재 작업에만 필요한 사실에는 호출하지 않는다.

에이전트는 별도의 저장 요청이나 확인 없이 관계를 추가·수정·삭제할 수 있다. 모든 관계는 사용자에게
승인받은 사실이 아니라 이후 대화에서 다시 고칠 수 있는 현재 해석이다.

## 관계 모델

- **Node**: 에이전트가 구분한 개념
- **Predicate**: 관계 유형
- **Edge**: 두 Node를 Predicate로 연결한 관계

이름과 관계 유형은 고정 enum이 아니다. 에이전트가 필요한 최소 구조를 만들고, 새 정보가 기존
이해를 바꾸면 같은 구조를 교체하거나 삭제한다.

## MCP 도구

`hypes_read`는 이름·별칭·설명 또는 이미 아는 참조에서 시작해 제한된 그래프 조각을 반환한다.
시작점이 없으면 이름순 목차를 보여 주며, 전체 점검을 요청한 경우에만 `continuation`을 사용한다.
읽기 연결은 스키마를 만들거나 쓰기 잠금을 획득하지 않는다.

`hypes_rewrite`는 `put_node`, `put_predicate`, `put_edge`, `delete` 연산을 한 SQLite 트랜잭션으로
적용한다. 어느 연산이든 실패하면 전체 patch를 되돌린다. Node나 Predicate를 삭제하면 연결된
Edge도 같은 트랜잭션에서 함께 삭제하며 결과에 그 수를 포함한다.

## 저장 경계

Hypes는 원 대화, 답변 전문, 프로젝트 사실·자료·출처, 자격 증명, 직접 식별자, 민감한 개인 특성,
Sense 지침과 Corpus 맥락을 저장하지 않는다. 에이전트가 이후 상호작용에 다시 쓸 관계만
`hypes-ontology.sqlite3`에 저장한다.

데이터 디렉터리는 현재 사용자 소유의 `0700`, 데이터베이스와 보조 파일은 `0600`이어야 한다.
심볼릭 링크, 다른 소유자나 안전하지 않은 권한을 발견하면 파일을 열기 전에 중단한다. 스키마 생성과
이전은 서버가 시작할 때 한 번 수행하고, 이후 읽기와 쓰기는 분리된 연결을 사용한다.

## 개발 범위

이 plugin 폴더가 실행 코드, 스킬, asset과 Codex·Claude manifest를 함께 보관하는 정본이다.
별도 패키지 생성, 평가 scenario, 결과 matrix와 판단 framework를 두지 않는다. 관계 저장·조회,
원자적 rollback, 참조 무결성과 비공개 저장 경계에 필요한 소수의 사례만 유지한다.
