# Hypes

Hypes는 에이전트가 현재 사용자를 이해하는 비공개 관계 모델이다. 저장된 관계는 다음 요청의
해석과 선택에 활용하며, 현재 사용자의 말이 우선한다. Sense는 장기 지침을, Corpus는 출처 기반
지식을, 대화 기록은 대화 시스템이 관리한다.

## 활용

Hypes의 저장 관계는 현재 해석·설명·질문·선택에 참여한다. 이번 상호작용에서 드러난 재사용 가능한
관계는 이후 대화를 위해 갱신한다. 관계없는 조회와 단순 변환은 현재 입력으로 수행한다.

에이전트는 별도 저장 요청 없이 관계를 추가·수정·삭제할 수 있다. 모든 관계는 사용자에게
승인받은 사실이 아니라 이후 대화에서 다시 고칠 수 있는 현재 해석이다.

## 관계 모델

- **Node**: 에이전트가 구분한 개념
- **Predicate**: 관계 유형
- **Edge**: 두 Node를 Predicate로 연결한 관계

이름과 관계 유형은 에이전트가 현재 이해에 맞게 구성한다. 새 정보는 기존 구조의 교체나 삭제로
반영한다.

## MCP 도구

`hypes_read`는 이름·별칭·설명 또는 이미 아는 참조에서 시작해 관련 그래프 조각을 반환한다.
시작점이 없으면 이름순 목차를 보여 주며, `continuation`은 전체 모델 검토를 이어 간다. 읽기
연결은 현재 스키마를 조회한다.

`hypes_rewrite`는 `put_node`, `put_predicate`, `put_edge`, `delete` 연산을 한 SQLite 트랜잭션으로
적용한다. 어느 연산이든 실패하면 전체 patch를 되돌린다. Node나 Predicate를 삭제하면 연결된
Edge도 같은 트랜잭션에서 함께 삭제하며 결과에 그 수를 포함한다.

## 저장 경계

Hypes는 이후 상호작용에 재사용할 비민감 관계를 `hypes-ontology.sqlite3`에 저장한다. 원 대화와
답변 전문은 대화 시스템에, 프로젝트 정보는 프로젝트에, 출처는 Corpus에, 장기 지침은 Sense에
귀속된다.

데이터 디렉터리는 현재 사용자 소유의 `0700`, 데이터베이스와 보조 파일은 `0600`이어야 한다.
심볼릭 링크, 다른 소유자나 잘못된 권한을 발견하면 파일을 열기 전에 중단한다. 스키마 생성과
이전은 서버가 시작할 때 한 번 수행하고, 이후 읽기와 쓰기는 분리된 연결을 사용한다.
