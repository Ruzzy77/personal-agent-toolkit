# Hypes

Hypes는 에이전트가 현재 사용자를 이해하는 비공개 관계 모델이다. 저장된 관계는 다음 요청을
해석하거나 선택할 때 필요한 범위에서만 사용하며, 현재 사용자의 말이 항상 우선한다. Hypes는
사용자 프로필, 지침 저장소나 대화 기록이 아니다.

## 사용 조건

Hypes는 다음 경우에만 작동한다.

- 저장된 용어나 관계가 요청한 결과의 명시적 입력인 경우
- 기존 관계가 현재 해석, 설명, 질문이나 선택을 바꿀 수 있는 경우
- 사용자가 Hypes가 무엇을 모델링하는지 묻는 경우
- 현재 상호작용에서 나중에도 유용할 관계가 드러나거나 기존 이해가 달라진 경우

관계없는 조회, 저장 관계에 의존하지 않는 단순 변환과 현재 작업에만 필요한 사실에는 호출하지
않는다. 에이전트는 별도의 저장 요청이나 확인 없이 관계를 추가·수정·삭제할 수 있으며, 일반적인
모델 정비를 답변에 보고하지 않는다. 모든 관계는 사용자에게 승인받은 사실이 아니라 이후 대화에서
다시 고칠 수 있는 현재 해석이다.

## 관계 모델

- **Node**: 에이전트가 구분한 개념
- **Predicate**: 관계 유형
- **Edge**: 두 Node를 Predicate로 연결한 관계

이름과 관계 유형은 고정 enum이 아니다. 에이전트가 필요한 최소 구조를 만들고, 새 정보가 기존
이해를 바꾸면 같은 구조를 교체하거나 삭제한다.

## MCP 도구

`hypes_read`는 이름·별칭·설명 또는 이미 아는 참조에서 시작해 제한된 그래프 조각을 반환한다.
시작점이 없으면 이름순 목차를 보여 주며, 전체 점검을 요청한 경우에만 `continuation`으로 다음
목차를 읽는다.

`hypes_rewrite`는 `put_node`, `put_predicate`, `put_edge`, `delete` 연산을 한 SQLite
트랜잭션으로 적용한다. 어느 연산이든 실패하면 전체 patch를 되돌린다. 연결된 Node나 Predicate를
지울 때에는 관련 Edge도 같은 patch에서 명시적으로 지워야 한다.

## 저장 경계

Hypes는 원 대화, 답변 전문, 프로젝트 사실·자료·출처, 자격 증명, 직접 식별자, 민감한 개인
특성, Sense 지침과 Corpus 맥락을 저장하지 않는다. 에이전트가 이후 상호작용에 다시 쓸 관계만
`hypes-ontology.sqlite3`에 저장한다.

데이터 디렉터리는 현재 사용자 소유의 `0700`, 데이터베이스와 보조 파일은 `0600`이어야 한다.
심볼릭 링크, 다른 소유자나 안전하지 않은 권한을 발견하면 파일을 열기 전에 `unsafe_storage`로
중단한다.

## 실행

```sh
uv sync
uv run hypes-mcp
```

이 plugin 폴더가 실행 코드, 스킬, asset과 Codex·Claude manifest를 함께 보관하는 정본이다.
marketplace도 이 폴더를 직접 설치하므로 별도 패키지 생성 단계가 없다.

## 개발 범위

Hypes의 정본은 이 plugin 폴더의 `src/hypes/`, `skills/use-user-model/`, `bin/`과 root manifest다. 모델 평가
scenario, 결과 파일, release checklist와 별도 판단 framework는 제품 저장소에 두지 않는다.

TDD와 전체 회귀를 일상 개발의 기본 절차로 사용하지 않는다. 관계 저장·조회, 트랜잭션 rollback,
사용자 데이터 권한처럼 실제 동작과 안전에 필요한 소수의 사례만 유지한다. 새 사례가 같은 경계를
확인하면 기존 테스트에 합치거나 중복 테스트를 지운다. 실제 배포에서는 plugin 시작과 기본 도구만 확인한다.
